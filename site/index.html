Brumel Browser

Less noise. More control.

An open-source Chromium-based browser designed around performance, privacy, reliability, and user control. We are building it in public, starting with the plan.

View on GitHub Read the roadmap Join the discussion

Philosophy

A browser can offer hundreds of features without running all of them all the time. Anything optional can be switched off completely, and when it is off it should cost nothing.

Chromium compatibility

Built on Chromium for maximum web and extension compatibility, with no Electron shell and no shortcuts on sandboxing or site isolation.

Local-first and optional

No mandatory account, telemetry or subscription for essential features. Your data stays on your device unless you choose otherwise.

Verifiable, not promised

Performance claims only come with reproducible benchmarks and raw data. Plans are labelled as plans.

Five pillars

Brumel is organised around five everyday promises. Optional local AI (Brumel Nano) runs across them and is never required.

Efficiency

Use fewer resources when your computer needs them: on battery, while gaming, on low-memory machines.

Memory

Never lose tabs, sessions, drafts or the context of what you were doing.

Clean Web

Native blocking of ads, trackers and web annoyances, with no advertising of our own.

Trust

Privacy by design, a transparent log of the browser's own connections, security first.

Everyday Tools

Small tools for common problems: compress a file while uploading it, export tables, search inside videos.

Roadmap

Phases are driven by dependencies, not dates. We will not promise release dates before we know our real development capacity.

  1. Phase 0 · nowPre-development. Identity, repository, documentation, research, feature catalog, architecture, licensing, security model.
  2. Phase 1Technical Foundation. Reproducible upstream fetch, first test build, branding, minimal patches, signed updater.
  3. Phase 2Internal Alpha. Basic browsing, initial UI, extensions, vertical tabs, Clean Web, memory management, session restore, measurements.
  4. Phase 3Public Alpha. First public, verifiable builds with Smart Optimize, Infinite Tabs, Time Machine, Glass Box and more.
  5. Phase 4Public Beta. Brumel Nano, workspaces, encrypted sync, accessibility, security audits, public benchmarks.
  6. Phase 5Version 1.0. Proven stability, reliable security updates, sustainable infrastructure.
  7. Phase 6Future. Android, more platforms, developer tools, isolated agents, community ecosystem.

Privacy & security

The Chromium security architecture (sandboxing, site isolation, fast security updates) is non-negotiable. We will never weaken it to win a benchmark.

Privacy by design

No mandatory telemetry, no account required, local-first data, opt-in only for anything that leaves your device. Privacy principles

Security model

Pinned upstream, signed builds and updates, SBOMs, private vulnerability reporting. Security policy

AI treats the web as untrusted

Local models run isolated, offline by default, and can never execute privileged actions because a web page asked them to.
